Search + Table

검색 조건과 결과 목록을 함께 쓰는 관리 화면 패턴 — Search Form · Table · Pagination · Empty State 조합

Overview

회원관리·주문관리처럼 조건으로 검색해 목록을 조회하는 화면에 쓰는 가장 대표적인 관리 화면 패턴이다. 상단 검색 영역 → 결과 테이블 → 페이지네이션 순으로 배치하고, 검색 결과가 없으면 테이블 대신 Empty State로 교체한다. spec.md 4-1(Search Form) 스펙엔 Date Picker도 포함돼 있지만, 이 패턴을 만들 당시엔 Date Picker 컴포넌트가 없어 제외했다. 이후 Date Picker가 추가됐고 patterns/search-form.html에는 기간 필터가 포함돼 있다 — 이 페이지(Search + Table)는 아직 검색어+상태만 있는 간단 버전으로 남아있다.

구성 요소

요소 설명
field 검색어 입력 (Input 기본형)
select 상태 필터 (Dropdown, 네이티브 select — 옵션이 적어 커스텀 드롭다운 대신 선택)
btn btn--primary / btn btn--default 검색(주요 액션) / 초기화(보조 액션) — Button
table + badge 결과 목록 (Table, 상태 열은 Badge)
pagination 결과 페이지 이동 (Pagination)
empty-state 검색 결과 없음 — 결과가 0건일 때 테이블을 대체 (Empty State)

Guidelines

✓ 권장

  • 검색은 btn--primary, 초기화는 btn--default로 위계를 구분
  • 검색 필드가 늘어나면 flex-wrap으로 줄바꿈, 가로 스크롤 강제하지 않기
  • 결과 0건이면 빈 <table> 대신 Empty State(검색 결과 없음)로 교체
  • 검색 조건이 바뀌면 Pagination을 1페이지로 리셋

✕ 지양

  • 검색/초기화 버튼을 둘 다 btn--primary로 동급 강조
  • Date Picker가 없다고 임의로 새 컴포넌트를 만들어 끼워넣기 — 정식 컴포넌트 제작 후 추가
  • 검색 결과 없음 상태에서 테이블 헤더만 남기고 tbody를 비워두기 (Empty State로 명확히 안내)
